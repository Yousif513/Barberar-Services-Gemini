    1: -- GOV-2 part 1: administrators read personal, bank, ledger, invoice and message data only through audited functions
    2: -- (Q4 and D4 final decision texts, docs/legal/2026-10-10-privacy-decision-memo.md, adopted 2026-10-10).
    3: --
    4: --   * No direct table SELECT for a console session (is_admin(): admin profile + console role + aal2 + not locked) on the
    5: --     tables that hold customer personal data, provider bank data, ledger rows, invoices, messages, staff records, addresses
    6: --     and health-intake data. The permissive administrator policies are dropped, and a RESTRICTIVE select policy on each table
    7: --     closes every other route (shared helpers, public catalogue rules). An administrator still reads their OWN rows where the
    8: --     table has an owner column (their profile, their consents), because they are that data subject.
    9: --   * The console reads that data through SECURITY DEFINER functions that are paged on the server, check the console
   10: --     permission, and write one audit event per read: actor, console role, action, target ids, fields, purpose, filter, row
   11: --     count, time, IP and user agent. Exports are built on the server, need step-up, and log the delivered row count.
   12: --   * Console permissions: personal.read (owner, operations) for customer, applicant, staff and message data; money.ledger
   13: --     (owner, finance) for the ledger, payouts, invoices and settlements; health.break_glass (owner only: no DPO role exists).
   14: --     Analyst and finance hold no personal.read; analyst and operations hold no money permission.
   15: --   * Health-intake answers have no administrator path except read_intake_answers_break_glass: owner, step-up, a written
   16: --     reason of at least 20 characters, an audit event without the answers, a security alert every other administrator sees
   17: --     and an out-of-band notice to every other owner.
   18: --   * The shared provider helpers (can_access_provider_operation / _wide) let an administrator through only with
   19: --     operations.write, so analyst and finance can no longer change provider-side data through them (GOV-1 gap
   20: --     analyst-read-only-not-enforced-through-shared-provider-helpers).

   22: DROP FUNCTION IF EXISTS pg_temp.patch_function(regprocedure, text, text);
   23: CREATE OR REPLACE FUNCTION pg_temp.patch_function(p_sig regprocedure, p_from text, p_to text) RETURNS void LANGUAGE plpgsql AS $patch$
   24: DECLARE v_def text := replace(pg_get_functiondef(p_sig), E'\r\n', E'\n');
   25: BEGIN
   26:   p_from := replace(p_from, E'\r\n', E'\n'); p_to := replace(p_to, E'\r\n', E'\n');
   27:   IF position(p_from IN v_def) = 0 THEN RAISE EXCEPTION 'patch_function: pattern not found in %', p_sig; END IF;
   28:   EXECUTE replace(v_def, p_from, p_to);
   29: END $patch$;
