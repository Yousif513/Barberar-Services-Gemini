# primora-dashboard-layout - PROPOSED

This staged 0.1.0-proposed package is not the recovered original or an installed skill. Read [proposal provenance](references/proposal-source.md). Pending scope/theme approval blocks screen generation, not source recovery.

Center the first loop on CEO request -> persistent task -> source-linked recommendation -> exact decision -> auditable follow-up. Preserve all 15 original identities and 42 proposed functions; one profile template serves all original identities. Keep company activation and business authority distinct from development workers and installed instructions.

Every agent profile exposes charter/source, associated and proposed skills, required versions/source/hash, missing capabilities, structural validation versus task-relevant independent behavioral evidence, evidence freshness, tools/prerequisites/permission state separately, and task-specific readiness. Add/remove/pin/evaluate recommendations route to a CEO decision, version diff and checked binding receipt. Never infer a competence percentage from guides or a role title.

Composer requirements drive readiness: capability/skill/version, source, output/acceptance, proposed owner/reviewer, scoped tools/data and limits. Unknown evidence stays unknown; missing instructions, failed cases or unavailable permissions name the blocked prerequisite. Reassess on changed requirements, version, evidence or authority. Inactive profiles remain non-executable.

Inventory exact page/action/overlay destinations before generation. Reuse component states rather than multiplying screens. Read-only history gets no generic create/delete/import. AR/EN/RTL, error draft preservation, empty/error/forbidden/stale and mobile recovery are requirements. Compare machine closure with the HQ action inventory; zero machine holes alone is not complete domain coverage.
