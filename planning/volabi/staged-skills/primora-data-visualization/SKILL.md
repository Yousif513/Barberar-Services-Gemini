# primora-data-visualization - PROPOSED

This staged 0.1.0-proposed replacement is not recovered original guidance or an approval. Read [proposal provenance](references/proposal-source.md).

For every metric declare the supported decision, definition/formula, authoritative source and permission scope, unit, timezone, interval, observation time, completeness/lag, owner, denominator, uncertainty and drill-down. Use SAR and Asia/Riyadh business dates. Preserve accounting meanings; charts must not alter pricing, commission, VAT or legal retention.

Show installed instructions, declared versions, structural validation, task-relevant behavioral evidence, available tools and actual permissions as separate columns. File presence, token counts and a charter do not establish competence. Readiness is a source-linked requirements assessment with met/missing/failed/unknown plus inactive/permission blocks. Never collapse missing evidence into zero or pass. Show underlying observation time and the approved freshness rule; leave unapproved validity durations unset.

Use accessible tables for exact comparisons and labelled matrices for skill gaps. Charts need text values/totals, units, source/time, color-independent status, AR/EN and bidi-isolated IDs. Distinguish empty, failed, partial, forbidden and stale. No demo fallback in release paths. Verify totals against authoritative records and test wrong-scope denial, stale updates and missing denominators. Token contrast does not replace rendered or assistive-technology evidence.
