## Observations (not filed as app defects)

- **PostgREST refuses a token in the second it was issued** (`PGRST303 "JWT issued at future"`). The first page load right
  after a session was minted got a 401 on `admin_session_state`. The console then silently hid role-gated actions: the reveal
  and payout buttons were missing and no message appeared. The suite now hands a session to a test only once PostgREST
  accepts it (polled, no fixed wait). A real operator who lands on a screen within the same second as sign-in could see the
  same silent trimming, because `admin_session_state` is not retried.
- **Granting the `operations` console role applies at once without a second owner.** `console_role_change_adds_privilege`
  is false for operations and analyst, and operations holds `personal.read` and `privacy.manage`. This may be deliberate
  (H-2 targets money and role powers). It is listed for the security pass to confirm, not as a defect.
- During the first route sweep the concurrent implementer's in-progress edit briefly left
  `web_platform/src/app/admin/ledger/page.tsx` unparsable. 2 routes failed with the dev-server compile error and passed on
  re-run once the edit was complete. It is not an app defect.

## How the suite works (determinism and safety)

- **Accounts:** every test creates its own throw-away accounts through the local GoTrue admin API (unique
  `e2e.*@primora.test` addresses, random passwords held in memory only) and deletes them afterwards. Console roles are
  assigned the way `supabase/seed.sql` does it. TOTP codes are computed (RFC 6238) from the secret GoTrue returned at
  enrolment, or from the secret the MFA page shows.
- **Data:** each test creates its own verified provider. The provider has one branch, one professional working 24 h every
  day, and one 60-minute service. The data is written as the service role, like the seed. Nothing is shared between tests,
  and append-only money rows simply remain in the throw-away database.
- **Time:** no `sleep`/`waitForTimeout`. Times come from the database clock (`dbNow`). Slots are found within a window
  relative to it, so neither the weekday, the hour nor the date matters. The 60-second IBAN timer and the midnight check
  use `page.clock`. The step-up rule ("TOTP older than 5 minutes") is reached by ageing `auth.mfa_amr_claims` and
  refreshing the session, never by waiting. Loading is judged from the page's own network events.
- **Safety:** `e2e/global-setup.ts` refuses any API, Mailpit or web address that is not on this machine. Every browser
  context aborts requests to `*.supabase.co/.in/.com`, `*.tap.company` and `*.gotap.com`. The browser's call to
  `payment-checkout` is answered in the test, so it never reaches the local functions runtime or Tap. Keys are never
  logged, and the CI job masks them.

## CI

`.github/workflows/deploy.yml`, job `e2e` (2 shards, `fail-fast: false`, 45-minute timeout). Steps:

1. `npm ci`.
2. Supabase CLI pinned to 2.106.0, started with the same 4-attempt retry as `verify-supabase` (Mailpit stays on; the
   Edge runtime stays off).
3. `supabase db reset`.
4. Masked stack settings go into `$GITHUB_ENV`.
5. `next build` against the local stack, then `next start -p 3100`.
6. `npx playwright install --with-deps chromium`, then `npm run typecheck:e2e`.
7. `npx playwright test --shard=N/2`.
8. On failure, `e2e/.results` (traces, screenshots), `e2e/.report` and the `next start` log are uploaded.

**Not yet run on GitHub Actions.** Nothing was pushed, so the job is unverified until the lead pushes. The local run used
`next dev`, not `next start`.
