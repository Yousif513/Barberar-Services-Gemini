# Held-checkout queue: local development delivery, 22 October 2026

Owner and finance console operators can now find and inspect held checkout attempts through a read-only queue with exact filters, oldest-first pagination, minimized details and audited refreshes. The new direct navigation entry opens `/admin/reconciliation/checkouts` without loading the parent reconciliation overview or triggering its escalation behavior. This is implemented and independently reviewed in the isolated repair branch; it has not been applied to a hosted database or released to production.

## Reconciliation operations

The queue includes submitting/unknown attempts and every record flagged for reconciliation, including captured or failed records and noncurrent quarantine evidence. List and detail return exactly eleven fields: attempt and payable IDs, purchase type, SAR amount/currency, recorded status, current/reconciliation flags and three timestamps. Contact information, request bytes/hash, checkout URLs and gateway/provider context stay private. Age is measured at the displayed server snapshot and adopts no resolution deadline.

Both SQL functions require the existing authenticated console session, MFA/live-session checks and `money.ledger` authority. Owner/finance keep their existing platform-wide minimized scope; no new business permission is granted. Raw table access stays revoked for every client role, including service_role. Successful populated and empty reads atomically record actor, role, purpose, fields, identifiers, filters and returned count. Audit failure prevents the data response. Neither function changes checkout, ledger, refund or reconciliation state.

English/Arabic controls support exact-ID/status/type filtering, page navigation, first-page recovery after the queue shrinks, missing details, visible read failures and retries, permission refusal, stale-response protection and keyboard focus. The table scrolls by keyboard at375px with bidi-isolated identifiers, SAR and Riyadh dates. A root review found misleading empty-page copy and duplicate current navigation entries; both were fixed before final acceptance. These controls cannot dispatch payments, retry charges, issue refunds, change flags, export private data or override outcomes.

The exact [API and operator contract](held-checkout-queue-contract.md) includes schema, scope, observation limits and sources. All15Headquarters business identities remain inactive. Azure signup/audio remains deferred, retaining Saudi male/Lebanese female preferences and the original single SAR10 all-in /100,000 aggregate-character /three-round audition allowance without reset. No real account, key, audio, fee or paid service was introduced.
